# 安装、默认配置与存档升级

当前是开发版本0.1.0，内部名称XianXia；版本以build.txt和原生包元数据为准。已验证官方tModLoader v2026.08.3.0（Terraria 1.4.4分支）下编译、打包与专服加载。完整通关、图形客户端和真实双客户端验收尚未完成；预览版或其它引擎版本不在当前验证范围。

## 安装开发包

1. 在GitHub最新成功的Native checks运行下载诊断artifact并解压，找到save/Mods/XianXia.tmod。它是开发验证包，未自动发布Steam Workshop。
2. 在tModLoader的模组管理界面打开模组目录，退出游戏后将XianXia.tmod放入该目录，重新启动并启用XianXia Mod；已有同名包时只保留一份。不要把整个源码或官方引擎归档当作模组安装。
3. 主机和所有客户端使用同一份XianXia包与相同引擎版本。首次尝试使用新角色/新世界，随后在备份后测试已有角色和世界。
4. 不需要安装Calamity。Boss Checklist可选；已有注册/加载检查，Boss Log页面仍需客户端验收。Calamity目前仅检测与日志，没有专门的进度或平衡适配。

本地构建见[检查入口](../Tools/SOURCE_CHECKS.md)，使用verify_build.ps1生成隔离包；正常ModSources构建时目录名称须为XianXia。构建排除Assets/Docs/Wiki/Tools和README；运行资源来自Common/Content/Localization。build.txt排除规则参考[官方文档](https://github.com/tModLoader/tModLoader/wiki/build.txt)。

## 正常游玩配置

| 服务端配置 | 默认值 | 含义 |
| --- | --- | --- |
| DebugDrops | false | 不额外掉落测试灵石/器胚；调试时开启会改变正常资源与经济 |
| PermanentGrowthMultiplier | 1.0 | 境界永久加成的基线，可设0至2；改变伤害/防御/回复等，不能当作当前平衡已验证的证据 |
| EnableWorldGeneration | true | 新世界创建时生成本模组生态；不在已有世界补生成或删除生态 |
| EnableSoftCompatibilityHooks | true | 允许可选集成；不自动安装依赖或提供灾厄平衡适配 |

多人以服务器配置为准。已有配置文件继续沿用保存值；新默认值不会覆盖玩家曾手动开启的DebugDrops。正式游玩前在模组配置中确认调试掉落关闭、成长倍率为1。关闭生成或旧世界可制作人工生态地块和五类物件，保留世界进度门槛；完整旧世界主线仍待通关验收。

## 更新与回退

- 退出所有相关游戏/服务器进程后，备份角色文件及配套模组数据、世界文件及配套模组数据、ModConfigs与当前XianXia包；云存档另保留离线副本。实际存档位置使用tModLoader界面打开目录确认，专服采用其配置的SavePath。
- 替换同名包并使用备份副本检查境界/灵气、品质丹药、铭刻/淬炼/觉醒/道化、Boss击败/声望/委托与终局路线。出现问题保留日志、引擎版本和提交号。
- 当前保留内部物品/本地化键；第97轮只更改英文显示名称，不改变存档身份。丹药品质存档版本1，装备淬炼写版本3；缺失字段按现有规则默认/归一化，高级成长依物品资格清理。已有规则回归通过不证明所有历史存档和其它模组组合都兼容。
- 委托世界同步追加新位，已有前五项顺序保持；终局路线是世界状态，换世界不能视作同一路线。库存和角色文件仍沿原版客户端模型，详见[网络所有权](NETWORKING.md)。
- 不承诺用旧包读取新包已保存的数据。回退时同时恢复匹配的包、角色、世界和配置备份，避免把删除内容或格式变化造成的数据损失带回正式存档。

## 当前验收限制

源码、原生包和专服加载成功不能证明真实战斗公平性、经济平衡、主线可获得性或多人同步。部分图标、宠物、翅膀、时装和物件仍复用素材，独立动画/声音与穿戴显示待验收；README中的“已实现”只指代码。完整状态与剩余要求见[剩余清单](PROJECT_REMAINING_TODO_2026-10-05.md)。素材来源及原创权属记录尚未完整整理，不能仅因仓库存在PNG认定原创/已验收。
