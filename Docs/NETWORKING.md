# 修行与多人网络协议

当前实现使用 tModLoader 标准 ModPacket、ModPlayer 和 ModSystem hook。协议变更要求客户端与服务器使用同一构建。

## 状态所有权

- Terraria 角色沿用客户端存档：加入时只允许该连接导入一次经过完整范围与状态关系校验的角色快照。此兼容行为不等于验证存档真实性，不宣称阻止修改本地角色存档。连接结束后释放该玩家槽位的导入标志。
- 游戏进行中的境界提升与天劫重试来自实际持有物品请求；服务器核验玩家存活、槽位、类型、数量、逐阶规则、世界进度和前置 Boss。客户端不能用状态上报替换境界。
- 天劫计时、敌怪/敌对弹幕、成功感悟与失败次数由服务器结算。客户端维持对应显示与 Buff，不自行完成试炼。失败虚弱记录保存于角色数据，死亡期间暂停，在复活后继续施加。
- 当前18件灵气武器（含3种法阵）的普通施放创建与灵气消费由服务器处理。客户端不能提交运行时灵气余额；其消费/恢复方法受到客户端角色状态保护，自动回气也只在服务器/单人运行。引气、突破、恢复药/禁符等12种修行道具使用库存事务。青木法阵恢复与雷阵周期落雷由服务器执行。

## 消息

第271轮MedicineSpiritBolt沿原版弹体同步新增1字节取消布尔值，完整读取后只可锁定取消并维持Magic，旧false包不恢复伤害。生成时仅权威端记录主人槽位/对象/会话，失效停止伤害并至多6tick退场；客户端即时会话比较仍未覆盖。此弹体额外AI布局已变化，双方需同一构建，未新增自定义消息号或会话传输，也不改变原版友方伤害信任模型。

第270轮三类持续法阵沿权威主人会话绑定过滤恢复、脉冲、落雷与药灵波次，旧会话移除并锁定失效，强制重激活不恢复效果。沿现有原版销毁同步，不新增消息或额外AI字段；客户端即时会话比较与真实运输尚未验证，已释放子弹幕的独立生命周期继续待检查。

第269轮剑轮、玄炉投锤、余烬冲击与雷匣三落共用权威端生成时主人槽位/对象/会话绑定。会话失配先拒绝伤害并按既有取消字段退场；旧投锤销毁不能释放新会话冲击。无新网络字段，客户端仍依现有主人状态及取消包，不即时比较服务器会话。原版友方伤害信任模型保持。

第268轮雷匣三落绑定权威端临时主人会话身份，初始化/死亡/进入世界/读取存档/网络重置/合法首次导入使旧身份失效，拒绝导入与普通资源快照不替换身份。此编号不保存或传输，既有雷击额外AI仍为近战标记与取消标记2字节；客户端同槽位即时身份判定尚未覆盖，继续等待权威取消同步。此改动不改变原版客户端友方伤害信任模型。

第267轮本地材料界面焦点阻止同时发送战斗技能请求，滚动只改界面位置；关闭恢复原请求路径。无新消息或字段，服务器仍独立验证所有请求，本地焦点不构成信任或安全边界。

第265轮终局路线导航和说明滚动仅修改本地预览，不发送消息或改写世界。鼠标和绑定确认共用原材料实例、玩家/库存状态、有效路线及尚未选择世界路线的重校验，继续发送既有消息11；服务端实际材料、境界、核心、斩道台和首次唯一选择规则保持，客户端预览无授权效力。

第263轮铭刻/炼器目标导航只更改本地预览和分页，不提交材料请求。鼠标及绑定确认共用工具/预览重校验后，继续沿消息9铭刻/淬炼/觉醒或消息12道化请求；无新增协议字段。客户端过滤不能代替服务端槽位、材料、进度及请求节流核验。

第262轮技能面板选择仅保存在本地输入组件，不写角色存档/资源快照、不同步给其它玩家。导航与取消不发包；显式施放先执行只读前置条件，再沿现有Request发送消息10。客户端不本地创建弹体或消费资源，服务端资格/材料/费用/节流与瞄准核验保持。

第261轮技能面板共用服务器只读前置条件判断，不可用按钮不发送消息10；预览不修改资源、库存、治疗或节流。允许请求仍须通过服务端连接/槽位/类型、节流及实际施放的瞄准/地形/消费核验，客户端预览不具有授权效力，消息布局保持。

第260轮天碑御印加入既有消息12道化事务，不新增布局；护体继续沿现有180tick保护/1200tick共享冷却同步字段。服务器与面板共用技能路线解析，避雷玉佩护体不继承手持其它法器的道化费用或收益。天碑道化护体成功后才应用重铸自疗/星渊灵压，路线失效恢复18基础灵耗护体。

第259轮雷纹剑匣加入既有消息12道化事务与3字节物品成长协议，不新增网络字段。雷匣三落沿服务器实际生效路线计算伤害、消耗、成功后的自疗或灵压；世界路线失配或核心缺失时恢复觉醒效果，失败整批回退不施路线效果。

第257轮在消息10既有布局追加技能编号7（ThunderVolley），原1–6不变。服务器验证实际觉醒雷纹剑匣，按当前武器参数创建三枚ThunderCaseStrikeProjectile；基础30灵耗/1200tick共享冷却，容量不足、几何阻挡及部分创建失败恢复资源、不启技能冷却。新弹体固定近战，原版弹幕额外AI为2字节：近战布尔值、取消布尔值；完整读取后应用，职业固定，取消不可被旧包恢复。权威端绑定生成时Player对象，失效停止伤害并在6tick内清理。第258轮补齐非法弹体几何的各端锁定取消与有限状态清理，隐藏且至多6tick退场，仅权威端标记同步。客户端依当前主人状态过滤伤害和表现并等待权威取消；客户端同槽新实例即时识别及真实双客户端运输未验证。不同构建仍不可混用。

共享MinorThunderboltProjectile使用2字节额外AI：职业标记（true为Melee，false为Magic）及只能锁定的取消标记。完整读取后应用；生成时从父弹幕取得职业，剑匣和雷阵雷击保留各自职业。权威端另绑定主人会话，失效无伤并至多6tick退场；会话编号不传输。双方需相同构建，此项沿用原版弹幕同步，不等同于服务器完整验证客户端派生伤害。

消息12为样例法器道化请求：材料槽位/类型、目标槽位/类型、Int32前缀、原铭刻、淬炼等级、觉醒布尔值、原道化路线及预览的世界路线。完整读取后服务器核验真实库存状态、所持道化材料、斩道境、核心击败标志及实际斩道台；按当前世界路线一次性修改目标并消费1印+36灵石，通过SyncEquipment同步所有变化槽位。旧消息9拒绝道化材料，避免将它当作清除石使用。

RefinedArtifact物品元数据版本3追加道化路线：等级字节、觉醒布尔值、路线字节共3字节；全部读完再应用。路线仅在三级且觉醒时保存，非法路线清为None，缺失旧字段不授予道化。物品跨世界仍保留路线，战斗收益只在匹配且已击败核心的世界生效。技能使用服务器实际道化记录计算消耗、伤害、治疗与灵压副作用。

消息11为世界终局路线选择请求：当前材料槽位、类型与路线字节1–3。服务器从连接确认玩家，核验初始化、存活、所持路线材料、渡劫境、旧天道核心击败标志及附近实际斩道台，再调用仅服务器可执行的TryChooseRoute。第一次合法确认固定世界路线并消费1材料；并发后续请求不覆盖、不消费。路线使用已有WorldData保存与广播，完成反馈以本地化NetworkText发给在线玩家。共享炼器事务的60 tick请求节流，整个请求读完才执行。

主动技能消息10由客户端发送技能字节、当前持有槽位、物品类型和瞄准位置。服务器从真实法器/饰品验证资格；七种技能共用玩家冷却，另有10 tick请求节流。飞剑使用服务器武器参数；治疗只处理阵内友方；护体由180 tick服务器计时决定。

完整快照现追加UInt16主动技能冷却与护体剩余时间；校验上限分别1200与180 tick，护体不得超过冷却。存档版本3保存技能冷却，护体不保存，加入快照也清除护体，避免重连恢复临时减伤。此项仍沿用客户端角色存档模型，不验证本地存档真实性。

## 生态与环境雷击

dedicated server 的八种生态使用每位玩家独立的方块扫描，范围沿用 Main.buffScanAreaWidth/Height，每60 tick刷新，移动超过8格立即重新扫描。客户端继续使用场景计数。服务器环境雷击在600像素范围共享420 tick冷却，避免附近玩家各自生成重复雷击；客户端仅生成 Dust。

## Boss 召唤事务

12种召唤物统一继承 CultivationBossSummonItem，保留原有配方、资源路径和 CanUseItem 条件。多人使用只发送库存请求，复制到服务器的普通 UseItem hook 不生成 Boss。服务器核验存活、连接快照、实际选中槽位、物品类型/数量与冷却，再执行原有境界、前置讨伐、世界阶段、生态、夜晚条件。

服务器先检查目标是否存在，调用 SpawnOnPlayer 后再次检查生成结果，成功才扣一份材料并同步库存；NPC槽位耗尽、条件变化或另一玩家先召唤均不扣材料。同一玩家按物品 useTime 设置请求冷却，防止重复包。单人模式也确认生成后才允许引擎消耗，失败不会消耗。标准库存槽位58在实际选中且服务器持有相应物品时也可请求；其鼠标界面交互仍需实机验收。

## 当前验证与待验收

### 装备铭刻

持有铭刻针/清除石在器胚炉、雷纹锻台、天火炉或斩道台附近使用，打开客户端目标选择面板。仅支持本Mod背包中的非消耗武器和非时装饰品；不支持弹药、堆叠装备、原版/外部Mod装备、鼠标槽或直接修改装备栏。选择捕获目标类型、完整前缀整数和原铭刻，确认使用捕获值；服务器从发送连接取得玩家，检查实际选中材料、存活、控制状态、连接导入、目标状态和附近实际方块，旧状态变化时不消费。

服务器/单人修改装备实例品质字段后消耗1铭刻针及3下品灵石，清除只消耗1清除石；同铭刻或空铭刻清除不消费。共享1秒事务间隔防重复确认；目标及材料使用标准SyncEquipment广播，GlobalItem枚举数据通过标准物品保存/网络载荷同步。普通角色/库存真实性仍沿用Terraria模型。目标以槽位、类型、前缀和原铭刻核对，不提供跨所有Mod自定义状态的物品身份证明。

同类持有/装备被动通过每tick种类位集去重，武器自身伤害/暴击/击退由标准GlobalItem属性hook单独计算。星渊累计生效120tick增加4灵压，仅服务器/单人执行；切换装备暂停累计但不重置，死亡清零。原有灵压恢复仍生效，不保证所有境界下净灵压持续增加。界面、真正联机库存交错、客户端装备属性与外部Mod兼容仍待实机验收。

### 淬炼样例

消息9追加原淬炼等级字节与觉醒布尔值；所有炼器选择均捕获并核验原铭刻、原淬炼等级和原觉醒状态，客户端与服务器须同构建。淬灵晶从真实材料类型开启淬炼分支，仅接受已铭刻的破云飞剑和青木阵盘，每次升一级；服务器检查实际境界、对应世界Boss标志、工作台和6/12/18灵石后，消费1晶和灵石。满级及所有失败不消费。等级独立存于RefinedArtifact GlobalItem，以等级字节和觉醒布尔值的物品载荷保存同步，非法值归零；普通库存及保存真实性仍沿用Terraria模型。

两件样例的每级4%伤害通过GlobalItem标准伤害hook影响正常发射参数，不修改Item.damage本值，不改变阵盘治疗。请求回归证明门槛和材料事务源码的行为，尚未证明真实引擎Hook路由、伤害落地、图形界面或双客户端库存交错。完整T14链的主动技能与道化尚未完成。

### 灵草种植

栽培灵草使用标准放置与割草/挖掘流程，不增加自定义种植请求。RandomUpdate仅服务器与单人执行，每次推进通过SendTileSquare广播帧；客户端不独立生成生长随机。阶段存储于TileFrameX，沿用世界方块保存/网络同步。成熟掉落青木根及1–3种子，未成熟只返还一粒种子；掉落仍遵循原版方块采集模型，未声称服务器完整验证普通库存和采集来源。真实双客户端的种植、收获、保存重载与物品交互仍需验收。

### 发射与法阵

发射请求核验玩家存活、可使用物品、连接快照、实际选中物品、数量、有限瞄准值和共享攻击间隔。费用使用原武器觉醒条件及境界降耗；伤害、击退、弹幕类型、速度、useTime修正取自服务器武器与标准hook。其他射击hook可阻止默认弹幕；若未产生属于该玩家的新弹幕，恢复消费前的快照。弹幕容量耗尽不扣费。两阵盘共享8秒冷却并限制同类现存数量。

青木恢复按每位玩家同一tick最多一次授权，重叠字段不会重复回气/回血；服务器向所有者发送标准SpiritHeal通知，生命上限不发送额外恢复。雷阵落雷和穿云剑销毁时的云息由服务器生成。雷纹剑、星蚀分裂弩的OnHitNPC追加弹幕仍遵循tModLoader持有者命中hook；尚未改成服务器命中确认协议，不能将其当作所有友方伤害已完全服务器权威的证据。

网络、库存事务、生态与环境回归程序执行实际相关源码，但模拟 Terraria 引擎边界。Gameplay 回归加载实际 Mod 与 tModLoader 程序集，覆盖存档、快照应用和连接导入标志。编译、打包和 dedicated server 加载通过。
